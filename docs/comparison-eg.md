# 与 eg 方案的对比

本文基于《智能资讯卡片产品-设计指南-v1.2.pdf》，重点参考第 3–4、6–11、14 章。文件名为 v1.2，页眉仍标为 v1.1。当前方案见 [功能设计](product-design.md)，实现状态见 [Demo 说明](demo.md)。

eg 方案以首页卡片流、资产和我的为主要入口，包含标签聚合、筛选、最新排序、AI 追问及观点复盘。它并非只有推荐，但主动查找和浏览的路径没有独立展开。以下比较针对设计，实际阅读效率仍需验证。

## 主要改进及原因

| 设计点 | eg 方案 | 当前方案及原因 |
| --- | --- | --- |
| 阅读方式 | 以一屏一卡、左右滑动为核心 | 根据任务选择摘要、紧凑列表和图表，兼顾快速扫读、查找和深入理解。 |
| 主动获取信息 | 通过卡片流、标签聚合和筛选承接，搜索流程尚未完整定义 | 明确关注、搜索和主题入口，让用户可直接查看所需内容，不必等待推荐命中。 |
| 偏好反馈 | 右滑感兴趣，左滑不感兴趣，参与推荐权重调整 | 普通浏览与明确反馈分开，避免将已读、暂时跳过误判为长期偏好。 |
| 定期总结 | 有重点流读完提示，主要仍按单张内容组织 | 日报跨来源总结一个时间段，支持往期回看，与持续更新的信息流分工。 |
| 来源管理 | 支持用户添加公开账号、RSS、网站等来源 | 平台统一提供来源，用户在平台内关注，简化配置、控制质量并降低接入和维护成本。 |
| 首期目标 | 同时覆盖阅读、观点记录、复盘和成长设计 | 先验证找信息、核对来源和追问，暂缓需要长期记录与验证规则的功能。 |

## 吸收的设计

- **按内容类型突出重点**：资讯展示事实，异动明确统计周期，观点区分原话与 AI 解读。共用页面框架，不增加一级模块。
- **区分来源与结论**：可靠来源不保证每个结论都成立；转载不算独立证据，来源分歧应可见。首期不叠加复杂的可信度评分。
- **事件持续更新**：同事件合并，实质进展突出新增内容，重要更正通知曾接收该信息的用户。
- **推荐多样性**：适度加入跨主题内容，避免单一来源或话题占满信息流，同时遵守用户排除条件。不预先锁死探索比例。
- **提醒克制**：关注与通知分别控制，跨资产的同一事件合并提醒，支持频控和免打扰。

## 取舍与验证

eg 的卡片适合少量精选和逐条理解，仍可用于当前方案的简报或重点内容。是否采用取决于阅读任务，不统一强制为全屏滑卡。

关注、搜索和主题入口提高可控性，也会增加界面选项。因此只将关注、推荐、热门作为探索的主要切换，其他能力保持为轻量入口。

暂缓复盘和成长会减少个人积累感。后续若有明确需求，可先验证收藏附笔记，再考虑完整复盘体系。

评价设计时重点看重要信息是否容易找到、结论是否可核对、旧内容是否能找回，而不只看滑动次数、点击率或阅读时长。
