# 与产品需求方案的对比

Sift 希望先让用户顺畅完成四件事：了解重点、继续跟进、查看依据、带着上下文提问。下面分别说明原方案容易遇到什么问题、Sift 如何处理，以及实现上需要承担哪些工作。

依据为更新于 **2026-09-16** 的 `product-requirements.md`，线上入口为 [SIFT-docs PR #1](https://github.com/DigitalLabs-web3/SIFT-docs/pull/1)，核对以同内容附件为准。目标设计与当前实现分别见[产品设计](product-design.md)和[演示说明](demo.md)。以下复杂度判断来自功能所需的规则与维护工作，不是工期估算。

## 简报看一期重点，探索看后续变化

原方案的精选和“为你”都在推荐当前值得看的内容。精选还要保持 10–20 张、保留未读、刷新后补充重要信息（§§1.3、6.6）。例如，用户还有 20 张未读，又出现一条重大消息：是暂不加入、替换未读，还是突破数量上限？文档尚未明确。

Sift 将两种场景分开：简报保存截至某个时间的重点，读完即可结束；探索继续提供最新报道。下午出现的新进展直接进入探索，早上的简报仍保留当时的内容，收藏与回看也更容易理解。

实现上，动态精选需要同时处理容量、已读状态、补充、淘汰和重排。固定简报发布后只需保存当期结果，后续更新由探索负责。简报仍需要选材、整理、截止时间校验和版本保存；减少的是“用户读到一半，卡组又变化”的状态处理。

## 不必让每条信息都回答“利好还是利空”

原方案规定，没有主关联资产或不同资产影响不一致时，都显示“分歧”（§2.1）。这会混淆不同情况：一篇科普可能根本不适合判断方向；一项政策可能对不同资产作用不同；两家媒体也可能对事实说法不一致。用户只看到“分歧”，无法知道是哪一种。

Sift 先说明发生了什么、为什么值得读。需要分析影响时，再在正文或追问中说明具体资产、观察期限和依据。比如用户问“什么是资本开支”，解释概念即可；问“资本开支增加意味着什么”，再讨论条件与风险。

原方案还要求自然语言回答后固定附方向、周期等六字段判断卡，未明确普通查询是否例外（§1.6）。实现这类固定输出，不只是多画一张卡，还要判断每个字段是否适用、是否有依据，以及材料变化后是否失效。按问题组织回答可以减少无意义的生成和检查，但所有实际给出的分析仍需有依据。

## 用户能直接修改的偏好，更容易做可靠

原方案同时使用主动偏好、关注与自选、短期推断和确认记忆，并提供衰减、撤回与暂停（§§1.7、7）。例如用户只为理解一则新闻问了几次 BTC，之后推荐变多：用户需要知道该改兴趣、重置近期推荐，还是删除记忆。原方案已有意图区分等保护，但这些规则本身也需要持续验证。

Sift 先使用用户明确选择的关注、自选和偏好。临时阅读与提问不修改长期兴趣，保存偏好描述时展示识别结果。推荐说明实际关系，没有个人关联的合格内容仍可通过“重要信息”或“拓展视野”出现。

实现上，多层推断需要记录信号来自哪里、作用多久、如何解决冲突，以及撤回后如何停止使用；登录合并还要处理不同设备的选择。明确选择主要围绕保存、修改和撤销展开，规则更容易测试。自然语言偏好仍需处理歧义，无法识别的条件不能悄悄扩大。

## 先让人看清依据，再增加评级和通知

原方案已区分来源等级与事实状态，但列表把来源名称放进详情，常驻展示盾牌（§§1.9、2.1）。读者容易先看到“级别高”，却不知道是谁发布的。一篇文章又可能同时包含已确认数字与推测，整张卡的等级不能说明每句话是否可靠。

Sift 保留来源和时间，引用指向具体发布记录。相同发布可以折叠，不同报道继续独立；事件、专题和简报各自保留文案与依据。读者可以直接核对“谁在什么时候说了什么”。

更正也是如此。原文把九月改成十二月，但简报从未写过月份，就不必给该重点附上更正警告。原方案要求向读过实质更正内容的用户推送（§§1.9、6.7），仍需补齐来源修订如何影响各份摘要、译文和已读版本的规则。

实现上，版本与引用是两套方案都需要的基础。评级另需标准、复核和争议处理；更正推送还需判断影响、匹配读者、去重并处理发送失败。Sift 先做好准确引用和实际受影响内容的说明，再考虑主动通知。省去评分和推送不等于省去事实核对。

## 切换语言时，保持同一篇内容

原方案优先打开同事件的目标语言原生稿，也明确禁止阅读中自动替换、保留历史版本（§§5.6–5.7.3）。但同一事件的中文报道和英文报道可能由不同作者撰写，重点与事实范围也不同。再次打开时优先换稿，仍需解释用户究竟在看哪篇文章。

Sift 切换语言时保留同一内容与引用，其他语言报道继续作为独立材料。实现上可以按“具体版本与语言”复用翻译，不再为了语言切换增加代表稿选择及其与来源筛选的组合规则。翻译准确性、缓存和原文入口仍需维护。

## 外部连接背后是一项持续服务

原方案将读取外部关注、持续同步、推断主题和断开删除列为连接后的能力（§1.12），但附件没有给出各平台已验证的接口与授权范围。一个“连接”按钮背后，还需要处理授权过期、接口限额、重复同步、失败重试，以及删除后哪些数据必须消失。

Sift 先由平台维护公共来源，用户关注即可阅读，公共整理可以复用。平台采集本身仍有接入和维护成本，但暂不增加每位用户的账户授权与私人数据同步。遇到反复出现的覆盖缺口，再决定补充公共来源还是接入个人账户。

原方案已暂缓交易、投资复盘、价格提醒和自动追踪（§§1.1、1.13），这些不计入首版复杂度。异常信号仍需独立验证数据、阈值和误报处理，不能因为已有行情页就视作附带能力。

## 实现复杂度主要差在哪里

两套方案都需要可靠的采集、去重、版本、引用、翻译和问答。Sift 主要减少四类额外工作：动态卡组的状态变化、多层偏好的推断与纠错、个人账户同步、评级及主动通知。规则之间的组合减少，异常处理和测试范围也更集中。

与此同时，简报和专题需要选材、整理、核对及维护，不能把演示中的预写内容当成已完成的生产服务。应以同一批材料验证阅读效果，再记录处理延迟、人工修正次数和持续成本，判断这些选择是否真正更合适。
